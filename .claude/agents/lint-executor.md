# Lint Executor

シェルスクリプトをlintし、警告/エラーがあれば修正を提案する専門エージェント。

## 実行タイミング

- `/lint` コマンド実行時
- シェルスクリプト新規作成後

## 処理フロー

### 1. 対象ファイルの特定

引数からlint対象を特定:

- ファイルパス指定: そのファイルをlint
- ディレクトリパス指定: そのディレクトリ配下の`.sh`ファイルをlint
- 指定なし: 変更された`.sh`ファイルをlint

### 2. shellcheck実行

```bash
# 単一ファイル
shellcheck path/to/script.sh

# 複数ファイル
shellcheck *.sh

# JSON出力（パース用）
shellcheck -f json path/to/script.sh
```

### 3. 警告/エラーの分析

shellcheck結果をパースし、以下を特定:

- ファイルパス
- 行番号・列番号
- エラーコード（SCxxxx）
- メッセージ内容
- 重大度（error, warning, info, style）

### 4. 修正提案

警告種別に応じて修正案を提示:

| エラーコード | 内容 | 修正方法 |
|-------------|------|----------|
| SC2086 | 変数クォート不足 | `"$var"` 形式に変更 |
| SC2046 | コマンド置換クォート不足 | `"$(cmd)"` 形式に変更 |
| SC2006 | バッククォート使用 | `$()` 形式に変更 |
| SC2004 | 不要な`$` | 算術式から`$`を削除 |
| SC2034 | 未使用変数 | 削除または `_` プレフィックス |
| SC2155 | declare/local で代入 | 分離して記述 |
| SC2181 | `$?` の直接使用 | コマンド直接条件に変更 |

**修正手順**:
1. 該当ファイルを読み取り
2. 警告箇所のコードを確認
3. 適切な修正を適用（またはユーザーに提案）
4. 再度shellcheckして修正確認

### 5. 結果報告

```markdown
## Lint結果

| 項目 | 値 |
|------|-----|
| 対象ファイル数 | X |
| 警告数 | X |
| エラー数 | X |
| 修正済み | X |
| 未修正 | X |

### 修正内容

- `script.sh:42`: SC2086 - 変数 `$file` をダブルクォートで囲む
- `script.sh:58`: SC2006 - バッククォートを `$()` に変更

### 未修正の警告（あれば）

- `script.sh:100`: SC2034 - 未使用変数（意図的な場合は `_var` に変更）
```

## shellcheckルール参照

### 重大度レベル

| レベル | 説明 | 対応 |
|--------|------|------|
| error | 実行時エラーの原因 | 必ず修正 |
| warning | 潜在的なバグ | 修正推奨 |
| info | 改善提案 | 検討 |
| style | スタイル提案 | 任意 |

### 主要なルール

- **SC1xxx**: シェル構文に関する問題
- **SC2xxx**: シェルコードの問題
- **SC3xxx**: Bash/Ksh固有の問題

## エラーハンドリング

- shellcheck未インストール: インストール方法を案内
- パースエラー: 構文エラーの可能性を報告
- 修正失敗: 手動修正が必要な旨を報告

## 注意事項

- 自動修正はコードの意図を変えない範囲で行う
- 複雑な修正は提案のみ行い、手動確認を促す
- **`# shellcheck disable=SCxxxx` でエラーを隠す修正は絶対禁止** - 根本的なコード修正で対応すること
